# 개설강좌 스냅샷

초기 활성 자료는 사용자가 제공한 `강좌 목록_20260923230210979641.xlsx`이다. 2026학년도 2학기 개설강좌조회에서 내려받은 파일이라는 출처는 사용자 제공 정보이다. SHA-256은 `89a581d8aea3ac82284662409628449993577d976e637ee086eec3bfb16119ad`이다. 파일명에서 읽은 `2026-09-23 23:02:10 +09:00`은 조회 시각의 추정값이며 포털에서 검증된 시각이 아니다. 스냅샷에는 실제 가져온 시각도 별도로 있다. 이 최초 버전의 활성화 표시는 사용자 제공 파일을 구현 과정에서 검증했다는 뜻이며 학교 또는 관리자의 공식 확인을 뜻하지 않는다.

원본 4,373행과 18개 열을 행 번호와 함께 보존한다. 과목코드와 분반으로 묶은 2,192개 실제 분반에는 개설학과 및 대상 학년·교과구분 관계, 강의주차, 모든 요일·교시·강의실 구간을 보존한다. 12개 행의 특수 시간 표기는 해석되지 않아 7개 분반에 검수 표시가 붙었다. 해당 분반은 시간표 추천에서 제외해야 한다. 시간 공란은 비동기 확정이 아니다. 원격수업, 타대학 사이버강의, 고정 시간 유무는 독립적인 값이다. 원본에 있는 분반은 `listed`이며 폐강 여부, 실시간 수강 가능 여부, 학과 제한에 대한 확인 가능한 상태가 없어 별도 값이 `unknown`이다. 신청/대상 인원은 좌석 판정에 쓰지 않는다.

## 새 학기 갱신

새 파일은 다음 순서로 다룬다. 학교 로그인 정보나 비공식 API는 사용하지 않는다.

1. 관리자에게 받은 공식 조회 파일을 작업 공간에 놓고 학년도·학기, 출처, 조회 시각과 그 근거를 기록한다.
2. `node scripts/course-offerings.mjs import FILE 2027-1 SOURCE RETRIEVED_AT BASIS`를 실행한다. 열 검증 및 원본 해시 확인 후 `staged` 스냅샷과 기존 활성본 대비 변경점 파일이 생성된다. 기존 활성본은 유지된다.
3. 새 스냅샷의 행 수, 검수 표시, 추가·삭제·변경 분반과 폐강·시간·강의실 공지를 대조한다. 특수 시간 표기와 여러 대상 학과 행을 확인한다.
4. 관리자 검수가 완료되면 `node scripts/course-offerings.mjs approve SNAPSHOT.json REVIEWER`를 실행한다.
5. `node scripts/course-offerings.mjs activate SNAPSHOT.json`을 실행한다. 이전 파일은 보존되고 `active.json`만 해당 학기의 새 버전을 가리킨다. 승인되지 않은 학기나 존재하지 않는 학기의 강좌는 조회되지 않는다.

폐강과 시간·강의실 변경은 새 원본 또는 공식 공지 확인 후 새 스냅샷으로 갱신한다. 정규화 결과의 원본 해시와 가져온 시각을 확인해야 한다.

졸업요건 원본 파일은 프로젝트 루트에 놓고 `node scripts/rule-source.mjs stage FILE CURRICULUM_YEAR DEPARTMENT_ID`로 등록한다. 원본 해시, 적용 교육과정 연도, 학과, 검수·승인 대기 상태, 이전 원본 버전, 기존 규칙 버전·상태가 버전별 매니페스트에 남는다. `review MANIFEST.json REVIEWER`로 검수를 기록한다. `approve MANIFEST.json REVIEWER`는 같은 교육과정 연도·학과·원본 해시를 인용하고 이미 `approved` 상태인 기존 규칙을 확인한 뒤 그 승인 사실을 기록한다. 이 명령 자체는 규칙을 승인하지 않는다. 기존 `rules/packs` 및 `scripts/rule-pack.mjs`의 규칙 승인·검증 체계를 사용하며 새 원본을 등록한 사실만으로 기존 학번의 활성 규칙을 교체하지 않는다. 절차는 [RULE_PACKS.md](RULE_PACKS.md)를 따른다.
