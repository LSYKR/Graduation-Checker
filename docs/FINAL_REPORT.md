# 졸업나침반: 공식 근거와 도구 호출을 활용한 졸업요건 진단 LLM 서비스

## 1. 프로젝트 개요

대학 졸업요건은 총학점만으로 판단할 수 없다. 입학년도, 소속 학과, 신입·편입 구분에 따라 전공필수·전공기초·교양필수·영역교양·졸업인증 기준이 달라지고, 교육과정 개편과 대체과목까지 함께 확인해야 한다. 학생은 여러 공지와 Excel 파일을 직접 대조해야 하며, 실수했을 때 졸업이 지연될 위험이 있다.

졸업나침반은 학생의 성적 Excel을 구조화하고 공식 교육과정과 비교해 다음을 제공한다.

1. 졸업요건 충족 여부와 영역별 부족 학점
2. 반드시 확인하거나 수강해야 할 지정과목
3. 어학·봉사·현장실습·자격증 등 졸업인증 현황
4. 다음 학기 수강 후보와 공강 선호를 반영한 계획
5. 모든 판정과 답변의 공식 근거

MVP 대상은 `한국해양대학교 2022학번 컴퓨터공학과 편입생`이다.

## 2. 수업 학습성과와의 연결

| 수업 주제 | 프로젝트 반영 내용 |
|---|---|
| Transformer·LLM 이론 | 도메인 상담 모델의 역할을 의도분류·설명 생성으로 제한 |
| 토큰화·프롬프트 엔지니어링 | 학생 프로필, 검색 근거, 도구 결과를 구조화한 시스템 프롬프트 설계 |
| PEFT·LoRA·QLoRA | Qwen2.5-3B-Instruct 기반 의도·근거 설명용 선택 학습 파이프라인 |
| RLHF·DPO | 교사 응답 선호쌍 구축을 후속 실험으로 설계 |

| Agent·도구 사용 | 졸업판정, 과목추천, 인증확인, 요건설명 도구 호출 |

| 평가·벤치마크 | 규칙 정확성, 도구 라우팅, 근거 포함률, 개인정보 평가 |
| 멀티모달·Responsible AI | 향후 공지 PDF/이미지 OCR 확장, 현재 개인정보 최소수집·면책·근거 제공 |

## 3. 요구사항

### 3.1 학생 기능

- 입학년도, 학과, 학생유형을 설정한다.
- 종합정보시스템에서 받은 실제 Excel 파일을 업로드한다.
- 파일을 서버로 보내지 않고 브라우저에서 파싱한다.
- 영역별 충족·부족, 지정 미이수과목, 졸업인증을 확인한다.
- 자연어로 질문하고 도구 호출 및 공식 출처가 포함된 답을 받는다.
- 졸업 목표와 공강 선호로 수강 후보를 조정한다.

### 3.2 운영자 기능

- 학교 홈페이지에서 받은 원본 교육과정 파일을 등록한다.
- 구조화된 규칙과 원문 URL, 적용년도, 검수일을 함께 관리한다.
- 공식 Excel의 오류나 학과 확인값은 삭제·덮어쓰기 대신 override 이력으로 남긴다.
- `university → admissionYear → department → studentType` 키로 여러 학교를 확장한다.

## 4. 실제 성적 파일 분석

실제 파일의 첫 시트는 50개 행이며 열은 다음과 같다.

`No, 년도, 학기, 교과목번호, 교과목명, 교과목구분, 시간, 학점, 등급, 담당교수, 교과목명(영문)`

구현 시 확인한 예외는 다음과 같다.

- 과목번호는 숫자와 영문이 섞이므로 문자열로 보존한다.
- `09230`처럼 앞자리 0이 있는 코드가 존재한다.
- `편입생 인정학점` 행은 등급이 비어 있어도 학점을 인정한다.
- `이수필`과 0학점 필수과목을 처리한다.
- F, NP, 미이수, 일반학기 등급 공란은 취득학점에서 제외한다.
- 재수강 중복은 과목번호 기준으로 한 번만 합산한다.

실제 파일 검증 결과 총 133학점과 다음 영역별 수치가 일치했다.

| 영역 | 원본 집계 후 규칙 보정 | 최소기준 |
|---|---:|---:|
| 교양필수 | 24 | 26 |
| 교양선택 | 19 | 17 |
| 전공기초 | 16 | 15 |
| 전공필수 | 48 (자동제어 대체 승인 시 51) | 60 |
| 전공선택 | 11 (자동제어 승인 시 8) | 12 |
| 일반선택 | 15 | 10 |
| 총합 | 133 | 140 |

## 5. 규칙 엔진

결정형 규칙 엔진은 `과목 정규화 → 이수판정 → 중복제거 → 분류 보정 → 영역 집계 → 지정과목 확인 → 졸업인증 확인` 순서로 동작한다.

핵심 보정 규칙은 다음과 같다.

- L1512, L1511, L1705, L1701을 2022 교육과정 기준 교양필수로 재분류한다.
- 51177 자동제어는 성적표의 전공선택 표기를 보존하고, 51181 자동제어Ⅰ 대체 승인 증빙이 있을 때만 전공필수로 옮긴다.
- 90585 인공지능및실습과 55249 심층학습및실습의 대체 인정은 학과 확인 대상으로 분리한다.
- 편입생은 조기졸업 대상에서 제외한다.

현재 성적표 회귀에서 확정 미이수로 표시되는 과목은 L1513, 90537, 51411, 54943, 90585의 5과목(12학점)이다. 51181은 이 목록에 넣지 않고 51177 대체 인정 확인 1건으로 분리한다.

## 6. RAG 및 Agent 설계

### 6.1 검색 지식베이스

공식 교육과정표, 교양 이수기준, 졸업인증 지침을 문서 단위와 조항 단위로 분리한다. 각 조각에는 학교, 입학년도, 학과, 학생유형, 문서버전, 원문 URL을 메타데이터로 저장한다. 검색 시 학생 프로필로 먼저 필터링한 뒤 의미 검색을 수행한다.

### 6.2 도구 계약

- `auditGraduation(profile, transcript)`: 영역별 충족·부족과 지정과목 반환
- `recommendCourses(audit, goal, preferences)`: 필수 우선 수강 후보 반환
- `checkCertification(profile, evidence)`: 어학·활동·자격 인증 판정
- `explainRequirement(ruleId)`: 원문 인용과 적용 이유 반환

LLM은 학점 값을 임의로 계산하거나 수정할 수 없고 도구가 반환한 JSON을 설명한다. 모델이 없거나 오류가 발생하면 같은 도구 계약을 사용하는 결정형 응답으로 전환한다.

## 7. PEFT 실험 설계

베이스 모델 후보는 Qwen2.5-3B-Instruct이다. 4-bit NF4 양자화와 LoRA rank 16을 사용하여 제한된 GPU에서도 실험할 수 있도록 했다. 학습 목적은 새로운 졸업 규칙을 암기시키는 것이 아니라 다음 두 작업의 형식을 안정화하는 것이다.

1. 질문을 audit, course-planning, certification, early-graduation으로 분류
2. 검색 근거와 도구 결과를 과장 없이 설명

정책·학점 값은 변할 수 있으므로 모델 가중치에 넣지 않고 RAG와 규칙 데이터로 관리한다.

## 8. 평가

| 평가축 | 방법 | 현재 결과 |
|---|---|---:|
| 규칙 정확성 | 재분류·편입학점·미이수·영역집계 단위평가 | 6/6 |
| 실제 파일 회귀 | 제공 성적표 총학점·6개 영역 비교 | 6/6 영역 일치 |
| 도구 라우팅 | 4개 의도, 12개 질문 | 12/12 |
| 개인정보 | 학번·성명 등 식별 열 제거 | 4/4 |
| 근거성 | 상담 응답에 공식 출처 1개 이상 요구 | 100% 정책 적용 |

현재 결과는 MVP 내부 평가세트 기준이며, 여러 학번·학과의 독립 표본으로 외부 타당도를 검증해야 한다.

## 9. Responsible AI

- 결과를 `충족/미충족`만으로 단정하지 않고 `조건부 판정`, `학과 확인 필요`를 구분한다.
- 답변마다 공식 원문을 연결하고 적용한 규칙 버전을 표시한다.
- 성적 파일은 기기 내에서만 처리하고 학번·성명은 데이터 모델에 넣지 않는다.
- 실제 성적을 저장소, 데모 데이터, 로그에 포함하지 않는다.
- 졸업 확정 권한이 없음을 명시하고 학사과·학과사무실 확인 경로를 제공한다.

## 10. 한계와 향후 계획

1. 현재 규칙은 2022 컴퓨터공학과 편입생만 완전 검증되었다.
2. 실제 수강편람의 분반·시간표 자동 수집은 아직 연결하지 않았다.
3. 대체과목과 학과별 예외는 담당부서 승인 워크플로가 필요하다.
4. 여러 학생 파일로 재수강·학점포기·복수전공 예외를 추가 검증해야 한다.
5. 다음 단계에서는 지능제어전공, 다른 입학년도, 다른 대학을 규칙 플러그인으로 확장한다.

## 11. 결론

졸업나침반은 LLM에게 졸업판정을 맡기는 서비스가 아니라, 공식 데이터와 결정형 규칙을 중심에 두고 LLM을 검색·도구 선택·설명 인터페이스로 활용한 프로젝트이다. 실제 파일에서 정확한 집계를 재현하면서도 RAG, Agent, PEFT, 평가, 배포, Responsible AI를 하나의 전체 생명주기로 구현했다.
